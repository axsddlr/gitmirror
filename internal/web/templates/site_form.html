Which token permissions are needed

Give each token only what it needs. A site you only copy from needs read access; a site you copy to needs write access, because gitmirror creates and updates the copies there.

GitHub

Create the token at {{.Data.GitHubTokens}}. A classic token is the simplest:

  • Copy from GitHub: repo (or public_repo if all repositories are public).
  • Copy to GitHub: repo, plus workflow if the code contains GitHub Actions workflows.
  • Webhooks set up by gitmirror: admin:repo_hook (and admin:org_hook for organisations).
  • Organisations must already exist on GitHub; gitmirror cannot create them.

With a fine-grained token: Metadata and Contents read to copy from GitHub (Starring read for starred repositories); Contents, Administration and Workflows write to copy to GitHub.

Gitea or Forgejo

Create the token at {{if .Data.GiteaTokens}}{{.Data.GiteaTokens}}{{else}}<your server>/user/settings/applications{{end}} (Settings, Applications).

  • Copy from it: read:repository, read:user, read:organization.
  • Copy to it: write:repository, read:user, plus write:organization to copy into an organisation or let gitmirror create one.
  • Webhooks set up by gitmirror: write:repository (write:organization for organisations), and the account must be an admin of the repository.
